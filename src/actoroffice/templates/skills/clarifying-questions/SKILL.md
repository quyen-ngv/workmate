# Asking good clarifying questions

1. **Ask only when it matters.** Ask when different interpretations would produce different results or an
   action that is hard to undo. Look up first: project files, tickets and documents, memory.
2. **One batch, early.** Put all questions in one message before you start, at most 5, most important first.
3. **Make answering easy.** Number the questions; give 2-4 concrete options each, mark your recommended
   default ("đề xuất: B"), allow "khác". Example:
   1. Ai duyệt đơn nghỉ? (a) quản lý trực tiếp — đề xuất (b) quản lý + HR (c) khác
4. **State the default.** "Nếu anh/chị không có ý kiến, em làm theo các phương án đề xuất."
   Record defaults you used as Assumptions in the document.
5. **Route to the right person.** Business intent and priorities → the user (ask_user / chat). Requirement
   details → the BA. Technical design → the Dev Lead (ask_colleague). Follow referrals ("hỏi anh X") — do not
   drop them.
6. **Close the loop.** Write the answers into the ticket / documents (and memory when reusable), then
   summarise the agreed scope in a few bullets before starting.
